## 一、做什么（一句话）

把在线 RAG 问答从 `src/routers/chat.py` 的 **~470 行硬编码串行管线**（手写 metrics×3、无协议版本、无错误/心跳帧、AI 消息用新 uuid 无幂等、错误拼进正文 `[错误:...]`、无 checkpoint、无 KB 权限边界）迁移为 **LangGraph 问答图**，并落地**阶段 0 冻结的 SSE v1 协议**。

## 二、为什么（大白话）

每次提问，之前是**一串写死的代码从头跑到尾**：意图识别→检索→融合→重排→回答→引用，每一步的统计数字都在别处手写一遍，改一处漏三处；用户问到一半 SSE 断了，AI 的回答就**丢了**；报错就**把 `[错误:...]` 直接拼进回答正文**，前端乍一看像模型在胡诌；也没有版本号，前端看不懂。

现在改成一张**图**：
- **流程收敛**：这些步骤变成一张有向图（节点 = `build_context`→`intent`→`retrieval`→`fusion`→`cite`→`answer`→`persist`），**图是唯一的编排真相**，`chat.py` 不再 470 行硬编码。
- **断线不丢回答**：SSE 用「后台任务 + 队列」驱动图，客户端断了**图自己继续跑完**、把 AI 消息落库；`done` 帧带 `message_id` 供前端**幂等去重**。
- **协议带版本、错误走帧**：每帧 `{v:1, ...}` 信封，向后兼容旧前端；失败走 `t:error` 帧，**不再污染正文**；新增 `t:heartbeat` 长流防网关掐断。
- **降级可观测**：意图/重排/检索失败**不再静默**——对应 `metrics.degraded=true` 记录原因，继续跑。
- **KB 权限边界**：普通成员只读（查询全开），**上传/建库仅 admin**（非 admin→403）。

> 对业务的影响：上传/检索/问答走同一套入库+问答逻辑；前端零改动消费新协议（`v` 信封向后兼容）。

## 三、技术实现

### 3.1 QAGraph（7 节点 + checkpoint）
- 节点链 & SSE 4 步映射：`intent→retrieval→fusion→answer` 四概念步 + `cite` + `done`。
- **checkpoint（C6 方案①）**：每节点边界落 Postgres（`AsyncPostgresSaver`），`thread_id = rag:{conversation_id}:{message_id}`；token 级内容**不进 state**（只写节点边界），避免高频序列化；断线/中断后从最后 checkpoint 续跑 → **重放 answer 段**（A-4.3）。
- **流式（C7 双通道）**：单一驱动 `astream_events(version='v2')`；节点经 `adispatch_custom_event('step'|'token'|'cite'|'done', {...})` 产出帧，投影器按事件名转 SSE；所有 `emit_*` **best-effort**（无运行上下文不崩管线）。心跳帧由**独立 asyncio task**（不放图内）。
- **并发（C8）**：async 图 + sync 阻塞节点（`asyncio.to_thread` 包 intent/召回/重排）；回答用 **`chat.astream()` async**（不阻塞 event loop）。

### 3.2 SSE v1 投影器（`interface/sse.py`）
帧构建 + 序列化 + `v:1` 信封单一真相源；metrics 由 `rag_metrics.build_rag_step` 单工厂。

### 3.3 ChatService（`services/chat_service.py`）
- 入口（短会话）/ 确保会话 / KB 存在校验 / 落库用户消息 / 读历史 / 分配 AI message_id。
- `_sse(initial)`：`task + asyncio.Queue(maxsize=500)` 解耦客户端生命周期与图生命周期；断连取消心跳 task、**不取消图 task**（图继续到 persist 落库）；错误 → `_on_error` 产 `t:error` + 落库 failed（content 空，无 `[错误]`）。
- 持久化一律短会话（`get_db_sessionmaker()()`），generator 不持有路由注入的长活 session（T-4.10）。

### 3.4 KB 鉴权（已与用户确认）
- **查询**：任何登录用户可用任何库（kb 存在→404；无 403）。
- **上传/建库**：仅 admin。`admin.py` KB 创建/删除/KB-scoped 上传本就 `require_admin`；**`main.py` 通用上传端点收紧为 `require_admin`**（非 admin→403）。
- 无需新增列/迁移。

## 五、测试（T-4.1~T-4.10，全绿）

| 编号 | 断言 |
| --- | --- |
| T-4.1 happy path | 四步 done + cite + done(message_id)；persist 落库 AI 消息含 citations+rag_steps |
| T-4.2 abort/resume | 同 thread 续跑仅重放 answer 段（recall 只跑一次）；不整条重来 |

## 七、风险与回滚

| 风险 | 处理 |
| --- | --- |
| 图未起（checkpoint 不可用） | `get_rag_graph()` 经 `get_checkpointer()`，chatservice 使用时报明确错误 |
| SSE 断连丢回答 | 后台 task 不随客户端断开而取消，图继续到 `persist` 落库（A-4.3） |
| token 重复（重试） | 不做节点内重试防 token 重复；断连续跑由 checkpoint 从 answer 段重放（全新 SSE 连接） |
| LLM/检索失败静默 | 降级节点记 `metrics.degraded`；answer 失败走 `t:error` |
| KB 越权 | 上传/建库 `require_admin`；查询校正（存在性） |
| **回滚** | 前端零改动（`v` 信封向后兼容）；`chat_stream` 改回旧管线即可；新图/服务/投影器独立文件，无侵入 |

## 八、结论

阶段 4 落地：在线问答从**硬编码串行管线 → LangGraph 问答图**，兑现"SSE 中断丢回答、失败静默降级、协议无版本、指标漂移"四类修复。QAGraph + checkpoint + SSE v1（`v` 信封 + step/text/cite/done/error/heartbeat）+ KB 写边界（admin-only）完成，前端零改动兼容。**下一步阶段 5**：脚本收敛、观测性（metrics/链路采集）与部署收尾（docker 镜像/健康检查/scale）。
