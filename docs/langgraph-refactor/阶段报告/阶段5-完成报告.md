## 一、做什么（一句话）

重构收尾：**清死代码 + 补观测（日志/指标/追踪）+ 脚本收敛为 cli + 可部署（Dockerfile/compose）+ 前端类型自动生成 + 全量回归**。

## 二、为什么（大白话）

前面四个阶段把入库图、问答图、基础设施都重构好了，但还留着一些"尾巴"：
- **死代码**：一个没人用的 PDF 预签名接口 + 三份重复的"找 PDF"逻辑 + 一个没人调用的内联索引函数（`process_document`）；
- **没有仪表盘**：出了问题只能翻日志，没有指标看板、没有链路追踪；
- **脚本各写各的**：`scripts/` 里 11 个脚本共 1900+ 行，每个都 `sys.path.insert` 硬塞路径、还把入库/提交管线**又抄了一遍**（第三条并行路径）；
- **不能一键部署**：只有基础设施的 compose，没有应用镜像。

本阶段就是把这四条尾巴全部收掉。

## 三、做了什么

### 3.1 死代码清理（S-5.5）
| 删除项 | 说明 |
| --- | --- |
| `GET /api/v1/documents/{doc_id}/pdf`（预签名） | 已由 `/pdf/stream` 代理流替代；前端唯一活跃路径就是 stream |
| `_try_document_task_pdf` / `_try_minio_direct` / `_build_pdf_response` | 三套重复回退合并为单一路径 `_find_pdf_object_name` |
| `src/indexer.py::process_document` | 无调用者的内联 chunk→embed→ES/Milvus 旧管线 |
| `src/llm.py::get_embedding_model` / `get_sentence_transformer` | 死 wrapper（真正生效的是容器适配器的方法） |
| `scripts/*.py`（11 个） | 退役，迁入 `cli/` |

**顺带修复**：`fetch_l0_meta` 原来硬编码 `index="chunks"`，现由调用方线程 `kb.es_index`（`QaState.kb.es_index`），多 KB 场景不再查错索引。

### 3.2 观测基建（O-5.2，三件套同时冻结）
新增 `app/infrastructure/observability/`：
- **`logger.py`** — 结构化 JSON 日志（`{level, ts, msg, logger, ctx}` 单行），`setup_logging()` 在 lifespan 启动时调用；
- **`metrics.py`** — `MetricsRegistry`（Prometheus），指标清单对齐契约 4.2.1：`graph_node_duration_seconds{graph,node}` / `rag_total` / `rag_degraded_total{step}` / `retrieval_latency_seconds{backend}` / `rerank|llm|mineru_latency_seconds` / `queue_depth` / `quota_remaining` / `quota_rejected_total` / `llm_error_total` / `mineru_error_total`；经 `AppContainer.get_metrics()` 单例注入，新增 `src/routers/metrics.py` 暴露 `GET /metrics`；
- **`tracing.py`** — OTel `TracerProvider`（`init_tracing(exporter=...)`，测试用 `InMemorySpanExporter`），`instrument.py` 提供 `tracked_span` 上下文管理器（span + 延迟直方图 + 错误计数器）。

**插桩点**：RAG 图每个节点（`ChatService._sse` 在 `astream_events` 的 `on_chain_start/end` 上开 span + 记耗时 + 累计 `rag_total`/`rag_degraded_total`）；外部调用 `recall_dual` / `rerank` / `analyze_intent` / answer LLM / MinerU poll+download。

### 3.3 PDF Range（S-5.7）
`/api/v1/documents/{doc_id}/pdf/stream` 支持 `Range: bytes=x-y` → **206 + Content-Range**；越界 → 416；无 Range → 200 全量；支持 open-ended（`bytes=200-`）与 suffix（`bytes=-500`）。逻辑抽为纯函数 `_pdf_range_bounds(range_header, total)`，可单测。

### 3.4 脚本收敛为 cli（O-5.1 / S-5.1 / S-5.2）
`scripts/`（11 个，1922 行）→ **`cli/`**（11 个薄 CLI + `_common.py`），全部**去掉 `sys.path.insert`**，`python -m cli.<name>` 或 pyproject 的 `medrag-*` 脚本运行。**重复的管线逻辑改为复用既有 seam**：

| cli | 收敛为 |
| --- | --- |
| `import_es` | `src.indexer.es_bulk_write`（原内联 `helpers.bulk`） |
| `import_milvus` | 容器 embedder + `src.indexer.milvus_insert` → `MilvusAdapter.upsert_batch`（原内联 `model.encode` + `collection.upsert`，**第三条并行路径消除**） |
| `scan_submit` | `SubmissionService.submit()`（原内联 token 分组/分批/reserve-commit-refund/enqueue） |
| `run_chunker` | domain 唯一入口 `chunk_document` + 容器 MinIO |
| `init_es` / `init_milvus` | 复用 `es_mappings` / `milvus.schema`（红线提醒保留） |
| `migrate_doc_id` / `backfill_document_tasks` / `check_status` / `list_bucket` / `download_model` | 容器感知薄 CLI |

`cli` 已加入 `[tool.hatch.build.targets.wheel] packages`。

### 3.5 部署（O-5.3）
- **`backend/Dockerfile`**（python:3.12-slim + uv `sync --frozen --no-dev`；模型权重不打进镜像，卷挂载 `/app/models`）+ `.dockerignore`。
- **`docker-compose.yml`**：env 收敛为 `x-app-env` 锚点（密钥走 Compose `environment`/`--env-file`，`JWT_SECRET_KEY` 强制显式设置）；新增 `backend`（uvicorn --workers 2 + /health healthcheck）与 `ingestion-worker`（队列活性 healthcheck，可 `--scale` 横向扩展）；`embedding-service` 归入 `app` profile（`EMBEDDING_MODE=remote`）。
- `docker compose --profile app config` **校验通过**，服务齐全（8 基建 + backend/ingestion-worker/embedding-service）。

### 3.6 前端类型（S-5.6）
`npx openapi-typescript` 由后端 OpenAPI 生成 `frontend/src/types/api.gen.ts`（24 paths / 23 schemas），替代手工镜像。生成命令写入 T-5.10 测试 docstring（可复现）。
