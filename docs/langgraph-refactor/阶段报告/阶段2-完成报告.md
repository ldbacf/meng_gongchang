## 六、关键设计决策

1. **doc_id 硬切点（用户确认）**：在线通用 KB 的 doc_id 从全 32 位 md5 → 契约口径 `md5[:8]`（`doc_id_from(article_id, md5)`）。存量旧 chunk 成为遗留群（阶段 3 reindex 清理）；删除逻辑**双口径兼容**（`doc_id IN (md5, md5[:8], task_batch_id)`，`admin._cleanup_es_milvus` 修复了原"通用 KB batch_id 误作 doc_id"的 bug）。
2. **状态机 reset 语义**：`set_status()` 走迁移表（流水线正常流转，非法抛异常）；`reset()` **无条件**写 PENDING（重传/重扫/重试等人为重开）。修复 4 处现有非法迁移（main 重传、admin retry、scan_submit 重扫）。DB CHECK 用 `CheckConstraint(status IN (...))` 而非原生 PG ENUM（避免 CREATE TYPE 风险），先归一化脏值再建约束。
3. **统一入口 + L0 分流**：`chunk_document(md5, full_md, cl_v2, meta, title)`——meta 有 article_id → 完整 L0（期刊元数据）；无 → generic L0（`title` 入参保标题，通用引用不回归"未知文档"）。
4. **kb_kind 迁移初始化**：ADD COLUMN（server_default='medical_default'）→ 按 slug 回填（非默认库置 'generic'）→ CHECK，同事务同文件；admin 新建 KB 显式 `kb_kind=GENERIC`（不依赖列默认，防静默变 medical_default 停索引）。
5. **is_generic 消除**：`analyze_intent`/`answer`/`search_and_answer` 的 `is_generic: bool` → `kb_kind: KBKind`（**带默认值 MEDICAL_DEFAULT**，test/ 手动脚本零改动）；chat 用 `resolve_kb_kind(kb)`。
6. **golden 先冻结后重构**：动 chunker 前用**当前**实现跑 sample fixtures 冻结基线，重构后回归证明"搬家不改行为"。
7. **ts 双轨统一**：`default_pipeline_steps` 与全部步骤写入 ts 统一 float（main/admin/worker/scan_submit），消灭 ISO/float 混合。
8. **retry 索引步修复**：原"只改状态不入队"的静默 no-op → reset(PENDING) + 重新入队触发 worker 重跑（MinerU 已完成，重新下载产物 + 重索引，幂等）。
