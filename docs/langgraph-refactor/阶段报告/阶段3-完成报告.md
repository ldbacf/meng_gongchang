## 六、关键设计决策

1. **poll 暂停机制（C5）**：`poll_parsed`（单次 poll + poll_count 状态机）→ 条件边 `pause_wait`（只调 `interrupt("POLL_PENDING")`，零副作用）→ resume 时 `Command(resume)` 唤醒回 poll_parsed。poll_count+1 在 poll_parsed 返回值 checkpoint 化，resume 重跑仅 pause_wait（无重复计数）。时钟基准 `poll_started_ts` 入 state（崩溃重启不归零）。**已源码核验**：END 线程 `ainvoke(None)` 是空操作，interrupt 是唯一可靠暂停机制。
2. **index_document 子图**：编译对象挂同一 checkpointer，dispatch_index 循环手动 `ainvoke`（thread_id=`batch:{id}:doc:{md5}`，C10 继承命名空间）；跳过已 READY doc（DB 为准）；子图内禁用 interrupt。节点级 `RetryPolicy(retry_on=MineruTransientError, max_attempts=3)`（C4）。
3. **retry 必须经队列**（评审否决"API 直接 resume"）：索引失败 → reset(PENDING) + resume 队列消息（mode="resume"，batch_id=原批=checkpoint thread 键），worker 串行驱动；MinerU 失败 → 从 MinIO 读回 PDF 重新提交（新 batch_id）+ 旧批 superseded 标记（防旧消息回收踩新状态）。"禁止复用已消费 batch_id" = 不重放已 ack 消息。
4. **batch 锁**：`SET NX batch:{id}:lock`（TTL 300s + 处理期续租），XAUTOCLAIM 回收前查锁（未释放跳过）；superseded 同样短路。兜底 Streams 可见性超时在长批（>1800s）下的误回收缺口。
5. **同 thread 重入残留清理**：重入时旧 checkpoint 的 `fatal/error` 残留会污染路由（源码级发现）→ initial input 显式 `fatal=False, error=None`。
6. **JSONB 脏跟踪**：`task.pipeline_steps[key]=...` 就地修改不触发 UPDATE（SQLAlchemy 行为）→ 必须 `dict(steps)` 重新赋值。
7. **md5 unique 迁移（A-3.5 硬阻塞）**：0004 drop `ix_document_tasks_md5`(unique) → `uq_document_tasks_md5_kb_id`(md5,kb_id) + 保留非 unique 单列索引；跨 KB 复制新 task 成为可能。
8. **删除对账**：ES `delete_by_query` + 显式 refresh 后 count=0；Milvus 用 per-doc `query(count(*))`（**不用 num_entities**——集合级总数）；非终态删除 409（防删后复活竞态）。
