## 一、核心目标

阶段 2 建立**领域层**：把系统的高价值纯函数资产从业务编排与基础设施胶水中剥离出来，承载显式状态机，消灭魔法串。**这是 LangGraph 图（阶段 3/4）能够安全落地的前提**——图的节点应该调用纯函数，而不是内联业务规则。

1. **O-2.1 四聚合根**：`Document`（任务状态机）、`KnowledgeBase`（kb_kind 策略）、`Chat`（会话/消息/引用规则）、`Quota`（额度算法）归位领域层，领域零外部依赖。
2. **O-2.2 状态机显式化**：`TaskStatus` 改 SQL Enum/CHECK + 显式迁移表校验（非法跳转抛领域异常）；`pipeline_steps` 类型化 + 校验器，停用 worker 写非法 key。
3. **O-2.3 纯函数资产归位**：`FullMdParser`、`chunk_document`（唯一切分入口）、`RRF`、`SearchHit` 契约、`CitationBuilder`、意图/回答/扩展 prompt 模板全部入 domain。
4. **O-2.4 统一切分路径**：在线（`indexer.process_document` 内联重写）与离线（`scripts/run_chunker.py`）两条路径统一调用 `chunk_document` 单入口，产出同构 chunk。
5. **O-2.5 消灭 slug 魔法串**：`kb.slug != "zhong_guo_quan_ke"` 在 worker/chat/admin/main/backfill 的散布分支收敛为 `KBKind(kb_kind)` 策略对象，`is_generic` 布尔参数穿越消除。

## 二、开发范围（含边界）

### 2.1 包含（In Scope）

| 编号 | 工作项 | 说明 |
| --- | --- | --- |
| S-2.1 | 领域层目录 | `domain/` 包建立；`document.py` `knowledge_base.py` `chat.py` `quota.py` `pipeline_steps.py` `chunking/*` `retrieval/*` `rag/*` `services/submission.py` `ports/*.py` |
| S-2.2 | 状态机 | `TaskStatus` 枚举 + `DocumentStateMachine`（合法迁移表）+ DB 迁移为 SQL Enum/CHECK |
| S-2.3 | pipeline_steps 类型化 | TypedDict + 校验器；worker 停止写 `task.status.lower()` 等非法 key |
| S-2.4 | chunker 归位 | `FullMdParser` + `chunk_document` 迁入 `domain/chunking/`，**唯一入口**，含 meta/v2 表注回填 |
| S-2.5 | RAG 纯函数 | `SearchHit` 契约、`RRF(k=20)`、`CitationBuilder`、`query_expansion`、prompt 模板入 `domain/rag`、`domain/retrieval` |
| S-2.6 | 意图策略 | `QueryIntentStrategy`（Medical/Generic 两实现）入 `domain/rag/intent.py` |
| S-2.7 | KBKind | `kb_kind` 字段/常量 + `KBPolicy`（kb_kind→es_index/milvus_collection/prompt 策略）+ `KBTargetResolver`，替换 5 处 slug 魔法串与 `is_generic` 参数穿越 |
| S-2.8 | 统一切分路径 | `indexer.process_document` 内联重写删除，改调 `chunk_document`；`scripts/run_chunker.py` 同源 |
| S-2.9 | Ports | `domain/ports/*.py` 全量抽象接口（阶段 1 适配器实现之） |

### 2.2 不包含（Out of Scope）

| 项 | 说明 |
| --- | --- |
| 不建 LangGraph 图 | 阶段 3/4 |
| 不做 doc_id 存量迁移 | 阶段 3（本阶段统一**入口**，口径切换随阶段 3 迁移） |
| 不做基础设施 | 阶段 1 已完成 |
| 不改前端 | 契约值不变（枚举值不变，仅类型增强） |

### 2.3 边界与约束

- **domain 包内禁止出现** `sqlalchemy/httpx/redis/pymilvus/elasticsearch/langchain` 等外部依赖（仅 stdlib）。
- 状态机迁移表的校验必须**双端生效**：DB 层（Enum/CHECK）+ 领域层（异常）。
- 统一切分路径后，`indexer`/`scripts` 的 chunk 产出必须**字节级同构**（同 chunk_id/doc_id/content）。

**4.2.4 chunk 产出（统一入口后同构）**

- `chunk_document(md5, full_md_text, content_list_v2, meta)` 返回 `{doc_id, md5, total_chunks, chunks}`；`doc_id = meta.article_id 兜底 md5[:8]`。
- 在线与离线路径仅在外层编排不同，切分逻辑同一函数。

### 4.3 本阶段变更点

- `status` DB 类型从 `String(32)` 改为 SQL Enum/CHECK（存量脏值由 Alembic 迁移做兜底归一化）。
- worker 索引失败处不再写 `pipeline_steps[task.status.lower()]`，改按实际步骤名写。
- `is_generic` 布尔参数从 `chat/intent/answer/citation` 四层调用链中移除，改为 KB 策略对象。
