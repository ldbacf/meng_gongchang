## 一、核心目标

阶段 5 是**收尾与冻结**：清理债务、补齐观测与运维，让重构成果可观测、可部署、可长期维护。本阶段无新业务功能，只做工程化收口与全量回归。

1. **O-5.1 脚本收敛**：`scripts/*` 1781 行一次性脚本收敛为 `cli/` 瘦 CLI，**复用同一 service/graph**（预置文献导入复用 `index_document` 子图），消除第三条并行路径。
2. **O-5.2 观测冻结**：结构化 JSON 日志 + `/metrics`（Prometheus 或 OTel）+ 分布式追踪（span 覆盖图节点与外部调用），三项作为硬验收。
3. **O-5.3 部署落地**：backend 应用 + 独立 worker 两个 Compose 服务，Dockerfile、healthcheck、restart 策略、env/secrets 收敛、models 权重挂载；多 worker 横向扩展语义明确。
4. **O-5.4 死代码清理**：删除遗留预签名 PDF 端点、`search_with_intent` 死码、`_build_pdf_response`、`_fetch_l0_meta` 硬编码 index、多余 embedding 单例、PDF 三套回退。
5. **O-5.5 前端契约自动化**：`openapi-typescript` 由 OpenAPI 生成前端 types，消除手工镜像；PDF 代理流补齐 Range 断点支持。
6. **O-5.6 全量回归**：端到端回归 + 多进程部署验证 + 崩溃恢复验证，重构完成验收。

## 二、开发范围（含边界）

### 2.1 包含（In Scope）

| 编号 | 工作项 | 说明 |
| --- | --- | --- |
| S-5.1 | cli 收敛 | `cli/{init_es,init_milvus,import_es,import_milvus,run_chunker,scan_submit,check_status,backfill,migrate_doc_id,download_model,list_bucket}.py` 瘦 CLI，复用 `application` service/graph |
| S-5.2 | 预置文献导入 | 批调度复用 `index_document` 子图（读 parsed→FullMdParser→chunk→embed→双写），仅外包一层批/进度调度，端口与 doc_id 口径与在线同构 |
| S-5.3 | 观测基建 | `infrastructure/observability/{logger,metrics,tracing}.py`：结构化 JSON 日志；MetricsPort（prometheus_client/OTel）；trace（span 覆盖图节点 + ES/Milvus/DeepSeek/rerank/MinerU 外部调用） |
| S-5.4 | 部署 | backend `Dockerfile` + `docker-compose.yml` 增加 `backend` 与 `ingestion-worker` 服务（healthcheck + restart + depends_on）；env/secrets 收敛到 Compose；`models/bge-m3` 挂载 |
| S-5.5 | 死代码清理 | 删预签名 `/documents/{doc_id}/pdf`、`_build_pdf_response`、`search_with_intent`/`search_and_answer` 残留、`_fetch_l0_meta` 硬编码 index、重复 embedding 单例、PDF 三套回退合并 |
| S-5.6 | 前端契约 | `openapi-typescript` 生成 `frontend/src/types`（替代手工镜像）；前端 SSE 增加 error/heartbeat 分支（可选增强）；PDF 走代理流 + Range |
| S-5.7 | 全量回归 | 端到端回归套件 + 多进程（2 backend + 2 worker）部署验证 + 崩溃恢复验证 |

### 2.2 不包含（Out of Scope）

| 项 | 说明 |
| --- | --- |
| 不新增业务功能 | 除修复边界外无新需求 |
| 不做前端交互大改 | 仅类型生成 + 可选协议分支 |
| 不做服务网格/弹性伸缩 | 单机 compose 多进程语义即可 |

### 2.3 边界与约束

- 预置文献导入必须与在线入库**同构**（同 chunk_id/doc_id/content），验收字节级一致。
- 观测三项（JSON 日志 + /metrics + trace）必须**同时冻结**，不能只做日志。
- 死代码清理前先跑全量回归基线与 golden，清理后重跑确认无回归。
- `docker-compose` 从 8 服务增至 10 服务（+backend +worker），worker 为独立健康检查单元。

### 4.2 数据契约（本阶段落地）

**4.2.1 观测指标清单**

```text
# 图/管线
graph_node_duration_seconds{graph, node}          # 每节点耗时直方图
rag_total / rag_degraded_total{step}              # 问答量与降级量
# 检索/外部调用
retrieval_latency_seconds{backend: es|milvus}
rerank_latency_seconds / llm_latency_seconds / mineru_latency_seconds
# 容量/可靠性
queue_depth{queue}                                # 队列深度
quota_remaining{key_id}                           # 额度剩余
quota_rejected_total                              # 额度拒绝率
llm_error_total / mineru_error_total              # 外部错误率
# trace
span: graph node / es / milvus / deepseek / rerank / mineru（OTel）
```

**4.2.2 部署拓扑（compose 10 服务）**

```yaml
# docker-compose.yml 增量
services:
  backend:            # API：uvicorn app.main:app --workers 2，healthcheck /health
    build: ./backend
    depends_on: [postgres, redis, minio, es, milvus]
    environment: [通过 Compose 统一注入，不落 .env 明文]
    volumes: ["./backend/models:/app/models"]
    restart: unless-stopped
  ingestion-worker:   # 独立 worker：python -m app.application.worker
    build: ./backend
    depends_on: [backend, postgres, redis, minio, es, milvus]
    healthcheck: 队列消费活性探针
    restart: unless-stopped
    # 多 worker = 同一 Compose 服务 scale=2，凭队列认领锁保证单消费者
```

**4.2.3 env/secrets 收敛**

- 所有密钥（MinIO/DeepSeek/SiliconFlow/MinerU/JWT）进 Compose `secrets`/`environment`，代码零明文默认。
- 默认弱口令（minioadmin/minioadmin123/mineru123）仅存在于本地开发 compose，生产配置必须覆盖。

**4.2.4 死代码删除清单**

| 删除项 | 说明 |
| --- | --- |
| `GET /api/v1/documents/{doc_id}/pdf`（预签名） | 已由 `/pdf/stream` 代理流替代 |
| `_build_pdf_response` / `_try_document_task_pdf` / `_try_minio_direct` | 三套回退合并为 `_find_pdf_object_name` 单路径 |
| `search_with_intent` / `search_and_answer` | 阶段 4 已收敛，删除残留 |
| `_fetch_l0_meta` 中硬编码 `index="chunks"` | 改从 KB 目标解析器取 es_index |
| `llm.get_sentence_transformer` / 重复 embedding 单例 | 唯一工厂 |

### 4.3 本阶段变更点

- `scripts/` 从可执行路径变为薄 CLI（复用 `application`），`sys.path.insert` 直 import 消失。
- 前端 types 由 openapi-typescript 生成（若生成结果与现状有差异，以生成物为准并走契约评审）。
- PDF 响应支持 `Range`（`206 Partial Content`），`Accept-Ranges: bytes` 声明与实现一致。
